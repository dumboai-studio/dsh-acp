# 0.9.0

升级到 DeepSeek Harness `0.2.2-rc.5` 和 ACP SDK `2.9.1`。保留 ACP v1，客户端初始化时仍可协商 ACP v2 预览协议。

- v2 支持客户端通过 ACP 连接提供 MCP 服务器。支持 MCP `2026-07-28`，保留 stdio 和 HTTP MCP。工具更新和审批请求携带相同的调用 ID 及工具名称。
- v2 的 `session/prompt` 接受 `idempotencyKey`。并发重试只插入一条消息。只要原消息仍保留，重启后也能返回原消息 ID。
- v2 完成历史回放时发送 `replay_complete`，随后同步当前状态。重复关闭或关闭不活跃的会话会成功。恢复不存在的会话时，v1 和 v2 都在错误中返回会话 ID。
- 修改模型、推理强度或权限时，客户端会收到更新后的完整选项。适配 Harness 新的子代理生命周期接口，结束或取消前会等待所需的子代理工作收尾。

使用固定版本的 `npx` 配置时，把版本改成 `0.9.0`。全局安装的客户端配置可继续使用原启动命令。

```sh
npm install -g @dumbo-ai/dsh-acp@0.9.0
dsh-acp --version
```

## ACP v2 支持范围

支持普通会话的新建、列表、恢复和关闭，提示词排队与取消，消息与思考流式输出，工具审批、任务清单、会话标题和配置选项。`replayFrom` 支持 `start`。MCP-over-ACP 必须由客户端提供并使用兼容的 MCP 版本。

未声明额外工作目录、会话删除或分叉、子会话控制、结构化提问、客户端文件操作和终端视图等可选能力。客户端发送未协商的额外工作目录时，该字段会被忽略。

## 验证

- 类型检查、lint、构建和 55 项仓库测试通过。独立 npm 安装通过版本与命令入口检查，36 项 ACP 进程测试通过。
- 使用 npm `0.8.0` 创建三种权限的真实 Harness 会话，再分别用 v1 和 v2 恢复。六种组合均保留权限、模型、推理强度与历史，恢复后可流式续聊。旧版 SDK `2.1.0` 客户端也通过了 v2 初始化、续聊和回放验证。
- [ACP 兼容性测试工具](https://github.com/agentclientprotocol/acp-tck/tree/7c71c4d1af0994e73bdc100c9f7f6b98f2319cda)测得 v1 通过 82 项、跳过 68 项；v2 通过 168 项、跳过 147 项。两组均零失败。跳过项包括未声明的可选能力和测试未触发的场景。这不是官方认证。

测试使用可重复的模型响应和真实 Harness，未调用线上模型接口。
